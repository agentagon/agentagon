# Implementation map

Use this reference to locate the contracts, source and representative tests behind each capability. Start with the [capability overview](../capabilities.md) for usage and [product decisions](product-decisions.md) for design rationale.

For a connected explanation of these components, read [how Agentagon works](architecture.md). The [extension walkthrough](extending.md) demonstrates a proposed change through normalization, validation and retained measurements.

Capability IDs remain stable when files move. Test links identify relevant coverage; record actual validation results with the revision and environment in the PR or release record.

| Capability | Observable behavior and conditions | Implementation / representative tests |
|---|---|---|
| **EVAL-01 · Build or extend a benchmark** | Start from a goal, findings or review recommendations. The host edits an isolated preparation worktree using existing tests and permitted data; application source stays unchanged. | [Preparation](../../src/agentagon/experiments/preparation.py), [eval procedure](../../skills/fix/references/evaluation.md); [preparation tests](../../tests/test_evaluation_preparation.py) |
| **EVAL-02 · Check benchmark sensitivity** | Execute baseline and deliberately incorrect cases against declared expectations. Optional correct variants must demonstrate declared objective rankings and minimum separation. Crashed or vacuous checks cannot establish sensitivity. Preparation has its own trial/time budget and retry identities. | [Preparation](../../src/agentagon/experiments/preparation.py), [plan schema](../../contracts/v1/evaluation-plan.json), [budget schema](../../contracts/v1/evaluation-budget.json); [sensitivity and retry tests](../../tests/test_evaluation_preparation.py), [metric discrimination tests](../../tests/test_metric_discrimination.py) |
| **EVAL-03 · Independently review and freeze** | Bind source, files, inputs, seeds, metrics, coverage, execution evidence and independent review into a frozen package. | **EVAL-04 · Reuse and version an evaluation** | Produce a benchmark review branch and fix specification. Private inputs stay out of delivery; intended tests require declared delivery paths. `eval start --from` creates a new evaluator draft; compatible application revisions can reuse the evaluator through a fresh baseline. | [Preparation](../../src/agentagon/experiments/preparation.py), [engine](../../src/agentagon/experiments/engine.py); [package and holdout tests](../../tests/test_evaluation_preparation.py) |
| **EVAL-05 · Repair datasets without changing application source** | Create a new evaluation version with scoped additions, replacements and deletions. Bind independent review to the benchmark branch and compare coverage and sensitivity at a fixed application revision. Private inputs remain excluded from delivery; scores from changed datasets do not prove application improvement. | [Preparation](../../src/agentagon/experiments/preparation.py), [plan schema](../../contracts/v1/evaluation-plan.json); [version and deletion tests](../../tests/test_evaluation_preparation.py) |
